# Android-функціональність LowTube — чекліст паритету

База інвентаризації: WinForms `main` (`8c599ab`). Це acceptance checklist, а не твердження про вже реалізовану Android-функціональність. Статуси виставляти лише після Android-перевірки.

## Каталог і навігація

- [ ] Публічний YouTube playlist URL має metadata acceptance на Android6/API23 та Android13/API33; окремий Compose test передав incoming `ACTION_VIEW` у MainActivity та підтвердив внутрішній Search із тим самим URL. Відео не запускалося. Перша metadata-сторінка прийнята; continuation і queue expansion відкриті. На фізичному Redmi звичайний PackageManager resolver для цього host повернув лише раніше обраний YouTube клієнт, тому системну перевагу LowTube або вибір через chooser ще треба перевірити без самовільної зміни settings.
- [ ] Системні налаштування YouTube links відкриваються через одну дію Profile на Android6 та Android13: instrumentation перехопив Intent і підтвердив API23 `ACTION_APPLICATION_DETAILS_SETTINGS` та API33 `ACTION_APP_OPEN_BY_DEFAULT_SETTINGS`, обидва з `package:com.lowtube.android`; системні налаштування не змінювалися. На фізичному Redmi Android13 target Settings Activity раніше відкривалась окремою ручною перевіркою.

- [ ] Новий продуктовий shell за вимогою від 17.11.2026 має чотири основні вкладки: Search, For you/Recommendations, Subscriptions і Profile; інший функціонал винесений у меню More, Android EQ виключений. Kotlin/Compose навігацію зібрано; на фізичному Android13 вручну відкрито всі вкладки та меню More, LowTube лишився на передньому плані. 18.11.2026 `MainScreenTest#primaryTabsAndMoreMenuRemainReachableOnApi23` перемкнув усі чотири вкладки, перевірив їхню selection semantics і наявність пунктів Library/Queue/Downloads/Settings у More на API23 AVD; відео не запускалося. Profile має Credential Manager sign-in/switch/sign-out flow, але без Cloud OAuth конфігурації показує setup-повідомлення; реальний Google account acceptance ще не пройшов. Офіційний YouTube-клієнт не модифікується.
- [ ] Пошук тексту, розпізнавання URL, відкриття відео/каналу/плейлиста. На API23 пряме посилання `https://www.youtube.com/watch?v=6kp91gVA9To` відкрило єдину картку з назвою, каналом, тривалістю й датою; MediaSession залишилася `state=null`, картку не натискали. Додано збереження типу Shorts для `/shorts/{id}`; той самий прямий URL показав картку під Shorts і порожній результат під Videos. Додано підказки з 12 останніх локальних текстових запитів із пошуком за префіксом і кнопкою очищення; URLs не записуються. Compose acceptance на API23 перевірив показ обох текстових підказок, фільтр за введеним префіксом, очищення та відсутність URL в історії; тестові preferences ізольовані від даних LowTube. URL-каналу/плейлиста та повний мережевий сценарій пошукового тексту мають окремі acceptance-сценарії.
- [ ] Зовнішні посилання YouTube: додано `ACTION_VIEW`/`BROWSABLE` для youtube.com, youtu.be та мобільного/music піддоменів; singleTop MainActivity приймає валідні відео, Shorts/live/embed, playlist і channel URL та переводить їх у внутрішній пошук без автоматичного відтворення. `:app:assembleDebug` успішний і APK оновлено на фізичному Android13; на API23 AVD фактичний ACTION_VIEW watch URL відкрив картку Big Buck Bunny, а `@GoogleDevelopers/videos` — картку канального відео “EmbeddingGemma 2: How natively multimodal embeddings work”; відтворення не запускалось. 18.11.2026 фізичний implicit ACTION_VIEW YouTube URL відкрив раніше вибраний YouTube застосунок замість LowTube; явний запуск LowTube з тим самим VIEW intent повернув LowTube на передній план. Додано `ACTION_SEND text/plain`: на Redmi share intent із `https://youtu.be/6kp91gVA9To` відкрив Search і підставив URL у поле; playback не запускався. Системний `query-activities` включив LowTube серед `ACTION_SEND` адресатів; chooser відкрито та закрито без вибору/надсилання. У Profile додано кнопку системних налаштувань supported links; на Android13 цільова Settings Activity відкрилась без зміни перемикачів, API23 fallback ще не перевірявся. Playlist, Shorts і live intent ще не прийняті.
- [ ] Гостьові тематичні рекомендації через пошук показують картки на Android13 та API23 AVD; ViewModel тримає до чотирьох сторінок у bounded in-memory cache. Тепер вкладка For you локально чергує ці результати з кешованими новими відео каналів, на які користувач підписаний; дублікати прибираються, feed читається з SQLite на IO dispatcher. Це дає обмежену персоналізацію без передачі історії на сервер. Пошукове поле показується лише на вкладці Search. Змішаний порядок ще не прийнято на пристрої; мережеву зміну налаштувань і пагінацію теж треба перевірити. Офіційний Data API v3 не має методу для персональних рекомендацій поточного користувача, тож повна серверна персоналізація лишається окремим API/архітектурним обмеженням.
- [ ] Локальні й YouTube subscriptions, категорії, фільтр каналу, sync. Нова головна вкладка Subscriptions показує локальну агреговану стрічку, фільтри каналу/типу й явний refresh; додано кнопку отримання read-only `youtube.readonly` згоди та посторінковий `subscriptions.list?mine=true`. Дані з API зберігаються email-scoped окремо від локальних каналів, автоматично видаляються через 30 днів і при sign out; акаунтні канали позначаються підписаними, але read-only scope не може відписуватися від них. Debug APK зібрано й встановлено; Subscriptions відкрито на Android13/API33 і API23 AVD. OAuth/Data API acceptance недоступний до налаштування Google Cloud client/API. Потрібні API23/API33 sync, empty/error/expiry/sign-out acceptance, акаунтна відеострічка та подальше погодження write scope для remote subscription changes.
- [ ] Дії на відеокартках: меню More має Open URL, Copy URL і Share link. Open/share обмежені HTTPS YouTube-хостами. На API23 `VideoCardShareTest` пройшов 3/3: callback, `text/plain` з заголовком і URL, відмова сторонньому домену. На фізичному Redmi Android chooser відкрився з назвою та URL; його закрили без надсилання, LowTube повернувся на Home. Раніше Copy URL перевірено вставкою у пошук. Функцію відкриття у зовнішньому браузері ще не натискали; відтворення не запускалося.
- [ ] YouTube account history не реалізована. Profile має Credential Manager вибір Google account/sign out, а Subscriptions — окремий OAuth `youtube.readonly` authorization flow. Для реального OAuth потрібні Web client ID, Android client для `com.lowtube.android` та SHA-1; локальний Web ID читається лише з `lowtubeGoogleWebClientId` чи `LOWTUBE_GOOGLE_WEB_CLIENT_ID`. API subscriptions sync реалізований у коді, але не прийнятий без Cloud configuration. Локально зберігаються тільки профільні ім'я/email і email-scoped API channel data; ID/access token не зберігаються. Серверну автентифікацію не заявлено. Не зберігати/виводити client secrets; не просити пароль чи cookies.
- [ ] SQLite локальна історія та екран перегляду/очищення зібрані; v2→v3 відкрито на фізичному Android 13. Прогрес зберігається; перемикач `ResumePlayback` реалізований (типово увімкнений), його вимкнений шлях перевірений на API23/API33 із синтетичною збереженою позицією 15 s — старт був з 0 s. Реальний device acceptance старту з ненульової історичної позиції з увімкненим перемикачем ще потрібен.
- [ ] Канали: керування, додавання/видалення, їхні відео/Shorts/стріми. На картках Home/Search назва каналу тепер окрема клікабельна ціль, що передає canonical `/channel/{id}` URL до внутрішнього browse; API23 Compose acceptance підтвердив, що дія не запускає відео. API23 live metadata acceptance розв'язав `@GoogleDevelopers` і отримав 25 video items через canonical URL. На фізичному Redmi Note 8 назва каналу `School of Social and Political Science` відкрила внутрішню стрічку з карткою `Nuffield Research Placements at the Edinburgh Q Step Centre`; playback не запускався, після тесту LowTube повернуто на For you/Home. Channel filter/category mapping, live channel, Shorts і navigation persistence ще відкриті.

## Картки, дії та черги

- [ ] Картки метаданих/прев'ю та швидкий перехід до відео.
- [ ] Дії: відтворити, аудіо-only, додати до черги, завантажити, зберегти у локальний плейлист, підписатися/відписатися, відкрити URL у браузері та копіювати URL. Download пропонує відео або audio-only у вихідному форматі без transcoding; режим записується для retry. Downloads рядок показує формат/MIME; filename зберігає Unicode, замінюючи лише небезпечні символи. На API23 audio-only transfer чотири рази завершився HTTP 403 у DownloadManager; тестовий URL не містив `n` query. Окремо bounded 64 KiB direct Range probe отримав HTTP 206 і всі байти на API23 та API33, але той самий запит через DownloadManager завершився FAILED з reason 1008 на обох пристроях і 0 завантажених байтів. Probe job/file прибрані тестом. Це відділяє робочий прямий HTTP Range від проблеми DownloadManager; стабільне скачування, cancel, retry та resume не підтверджені й потребують власного Android transfer engine.
- [ ] Queue: локальне збереження, порядок, видалення/переміщення й очищення реалізовані; вибраний локальний плейлист пакетно додається до черги транзакційно зі збереженням порядку. На Android13 фізично перевірено появу тестового елемента в Queue і очищено лише тестові дані; process-death acceptance для нового пакета ще не пройдено. Playlist marker розгортається однією сторінкою за раз, continuation зберігається в schema v4; migration v3→v4 перевірена на Android13 та API23, але мережеве розгортання плейлиста ще не прийняте. Поточний елемент, manual Next/Previous та AutoNext уже є; код готує наступний елемент із черги приблизно за 20 секунд до EOF. End-to-end перевірка UI/queue шляху на API23/API33 ще відкрита.
- [ ] Перехід плейлиста зберігає аудіодоріжку потрібного елемента й ownership сесії.
- [ ] Черга та незавершений елемент переживають process death відповідно до правил Windows.

## Медіаплеєр

- [ ] Додано production fallback для `alr=yes` URL-object кандидатів: лише коли звичайний `n` transform не дав жодного прийнятного URL; runtime обмежує bundle/час/кількість кандидатів, а Kotlin приймає результат тільки якщо `n` змінився та HTTPS host/path збереглися. Синтетичний `PlayerUrl.gf` instrumentation пройшов на API23 та Android13. На поточному live bundle locator не знайшов `mI` marker candidate, тому саме production fallback на реальному YouTube потоці ще не підтверджений. Короткий resolver playback acceptance пройшов на API23 та Android13, але fixture не доводить, що був використаний marker fallback чи `n` challenge.

- [ ] Публічне відео програвалося короткими фрагментами на API23 AVD та API33 Android; `MediaSession` показала PLAYING, потік має кадри. Оновлений API-first resolver працює на обох; окремі DASH/audio-only/якісні сценарії ще потребують runtime проходу. Доданий opt-in Range acceptance без Media3 playback: на фізичному API33 і API23 AVD resolver отримав direct H.264/MP4 video та MP4 audio; для кожного CDN повернув HTTP 206 і рівно 65 536 байтів. Це підтверджує лише ці single-file формати на одному публічному ролику. 18.11.2026 full-bundle QuickJS probe на Redmi Android13 виявив `alr=yes` URL-object кандидат `mI`: метод `gf` змінив справжній MWEB `n` без підміни значення й без signature payload; URL зберіг HTTPS host/path та пройшов `acceptUrlNTransform`. Це лише opt-in діагностика, не production resolver і не playback acceptance; API23 fixture не повернув streaming challenge. Production інтеграція, інші клієнти/скрипти й bounded playback після зміни плеєра ще не підтверджені. PO token і SABR-only потоки теж не прийняті.
- [ ] Seek/позиція доступні в Media3 controls; watch progress зберігся після навігації (52% з 10:35). Автоматичний resume з цієї позиції ще не перевірено.
- [ ] Settings UI має максимум роздільності, перевагу H.264, межу 30 FPS і audio-only; на API23 та API33 всі параметри видно в UI, adaptive/audio metadata відбирається кодом, але відтворення з кожним зміненим параметром не перевірено.
- [ ] Playback speed: у плеєрі додано вибір 0,25×–2× з кроком 0,25×, значення зберігається локально і встановлюється в Media3. Фізично на Android 13 підтверджено 1,25× у MediaSession; значення 1× зчитано з SharedPreferences після force-stop/restart. Повторне застосування до нового player session та acceptance на API23 лишаються.
- [ ] Вибір аудіодоріжки та вбудованих субтитрів додано до UI через Media3; аудіо має Auto, субтитри мають Auto/Off, доступні треки формуються з підтримуваних Media3 groups. Runtime перемикання вбудованих аудіо/субтитрів ще не прийнято. Додано зовнішні `.vtt`/`.srt` субтитри та локальне зовнішнє аудіо через SAF із persistable read grant; зовнішнє аудіо зливається з відео на рівні MediaSource та зберігає playhead і Play/Pause при підключенні/видаленні. Bounded acceptance пройшов на API23 AVD і фізичному API33: окремий audio track підтриманий, відеопозиція досягла ~2 s, кліп обмежено 30 s. Реальний SAF picker/grant на обох API, `.srt`, revoke/missing grant, process-death і ручне перемикання вбудованих tracks ще відкриті.
- [ ] Queue/AutoNext/manual Next реалізовані в UI та Media3 listener. На API23 AVD раніше перевірено ручний Next із короткими фрагментами. Додано кнопку Previous: вона обирає останнє інше відео з локальної історії, а тест змінив заголовок на Big Buck Bunny. Тестовий запис мав resume біля 3:11, тому AVD одразу поновив цей media position; відтворення було негайно призупинене біля 3:24. Цей тест не зараховано як перевірку у межах 2 хвилин; наступного разу потрібна чиста позиція тестового запису. EOF/автоперехід навмисно не доводити до кінця відео. Android resolver запускає підготовку приблизно за 20 s до завершення; Media3 playlist preloading обмежений цільовими 5 s семплів. Перепідготовка скасовується при буферизації, виході з екрана, вимкнених AutoNext/PreloadNext або зміні першого елемента черги. API23 acceptance підтвердив перехід Media3 з 12-секундного кліпу на наступний елемент із ~1 s подальшого медіачасу; повний Compose queue/resolver шлях та API33 ще не прийняті.
- [ ] Android audio focus, wired/Bluetooth навушники, дзвінки/інтерупти, media session/notification, lock-screen controls і background playback.
- [ ] Поворот екрана, Picture-in-Picture за API-рівнем/дозволами, відновлення після Android process death.
- [ ] AutoRecover налаштовується й переноситься через PC JSON `AutoRecover`; код обмежує повтор до 2 спроб для тимчасових resolver/Media3 IO помилок, з backoff 1/3 s та відновленням позиції/швидкості/доріжок/paused state. Unit/UI/transfer тести проходять на API23, але fault-injection перевірка нового recovery handler і скасування застарілої job ще потрібні.
- [ ] Діагностика фактичного декодера, buffer/cache, media-time vs wall-time та A/V sync; requested hardware decode не видається за підтверджений.
- Код-база: `src/Player.cs`, `PlayerTuning.cs`, `StreamOpenRecovery.cs`, `StreamContinuity.cs`, `PlaybackTrace.cs`, `StartupTrace.cs`, `player/lowtube.lua`, `player/lowtube_osc.lua`.

## Завантаження

- [ ] Progressive відео MP4/WebM з вбудованим аудіо й аудіо MP4/WebM/MP3 обираються як direct single-file options; bounded transfer через власний OkHttp service із Range та resume пройшов на API23 і API33. Публікація завершеного bounded-файла у Downloads та перевірка байтів пройшли на обох системах; це не acceptance повного відеофайла або підтримки всіх контейнерів. ## Resolver обмеження станом на 15.11.2026
