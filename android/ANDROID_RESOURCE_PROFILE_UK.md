# LowTube Android — профіль ресурсів

Збираємо локальні знімки навантаження під час розробки Android-версії та оновлюємо їх для важливих сценаріїв. Це ручне вимірювання через ADB, не фонова телеметрія: дані не передаються назовні й не містять URL, історії перегляду, cookies чи вмісту пошуку.

## Методика

- Команда: `android/tools/Measure-ResourceUsage.ps1 -Serial <adb-serial> -SampleSeconds 5 -State <state>`.
- Скрипт читає `/proc/<pid>/stat` для CPU time та RSS, `dumpsys meminfo` для PSS, `/proc/meminfo` для загальної/доступної RAM. Він виводить тільки агрегати застосунку та пристрою; CSV створюється лише за явно переданим `-CsvPath`.
- CPU подано як частку одного ядра за коротке вікно. Результат залежить від стану UI, decoder, відео, фонового GC, пристрою та розміру вікна; одиночні значення — орієнтир, не benchmark.
- Порівнювати API23 x86_64 AVD із телефоном напряму не можна: AVD працює зі SwiftShader software GLES та іншим CPU/decoder шляхом.
- Для будь-якого програвання відео зупиняти тест на перших 2 хвилинах медіапозиції; через прискорений/нестабільний media clock AVD краще брати короткі інтервали до 60 секунд і часто звіряти playhead. Після зрізу відтворення зупинити, щоб не продовжувалося у фоні.
- Відтворення запускати лише при зміні функціоналу самого плеєра; для перевірок пошуку, бібліотеки, локалізацій та екранів не запускати відео.

### Тлумачення

Пошук додає приблизно 23 MiB PSS проти щойно перезапущеного home на Android 13; у AVD пошуковий екран показав близько 69 MiB PSS. Значення PSS/RSS змінюються після мережевого запиту й завантаження прев'ю, а RSS містить спільно відображені бібліотеки; оцінку власного впливу краще будувати на PSS. Телефонний CPU-зріз у видачі був 7,6% одного ядра, але це лише 5 секунд і включає завантаження карток/зображень. Відеодекодування на SwiftShader AVD не характеризує споживання фізичного пристрою.

## Наступні профілі

- Для кожного нового playback, downloads, settings та background сценарію знімати idle baseline і стан дії однаковим інтервалом.
- Для відео запускати максимум 60-секундні зрізи на AVD і не довше 2 хвилин медіапозиції на будь-якому пристрої; зупиняти при першому підтвердженні потоку/стану та відразу записувати PSS/RSS/CPU.
- Зіставити CPU/RAM з вибраною якістю, codec та screen state лише після кількох повторів на одному пристрої; одиночні зрізи не є підставою заявляти оптимізацію.
