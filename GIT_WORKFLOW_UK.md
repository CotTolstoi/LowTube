# Git у процесі розробки LowTube

## Модель роботи

- `main` містить останній зібраний і перевірений стан LowTube.
- Кожне завдання виконується в окремій гілці від актуального `main`.
- Назви гілок: `fix/<короткий-опис>`, `feat/<короткий-опис>`, `docs/<короткий-опис>` або `build/<короткий-опис>`.
- Після завершення перевірок зміни зливаються в `main`. Для одиночної локальної розробки можна зробити звичайне fast-forward злиття; паралельні чи довгі роботи зберігаються окремими гілками.
- До `main` не потрапляють незавершені або неперевірені зміни.

## Рекомендований цикл завдання

```powershell
git switch main
git pull --ff-only                 # лише якщо для репозиторію налаштовано remote
git switch -c fix/короткий-опис

# редагування та перевірки
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Build-All.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Run-Checks.ps1
git diff --check
git status --short
git diff

git add <перевірені-файли>
git diff --cached --check
git diff --cached
git commit -m "fix: короткий опис"

git switch main
git merge --ff-only fix/короткий-опис
```

Не запускайте `git add .` до перегляду `git status`: додавайте лише вихідний код, тести й документацію, потрібні для конкретного завдання. Для змін коду запускайте `Build-All.ps1`, який збирає всі чотири власні програми разом, а тоді відповідні перевірки з `Run-Checks.ps1`. Звітуйте окремо про збірку, офлайн-тести, Windows runtime і реальну перевірку GPU/аудіо.

## Коміти

Формат повідомлення: `<тип>: <короткий опис>`.

Типи: `feat`, `fix`, `perf`, `refactor`, `test`, `docs`, `build`, `chore`.
Один коміт має описувати одну логічну зміну. Не включайте в коміт згенеровані EXE, архіви релізу, кеші встановлення, особисті налаштування, історію, cookies, сесії браузера, OAuth-дані чи локальні діагностичні файли.

## Публікація та відновлення

Цей каталог використовує локальний Git. Remote не налаштовується автоматично. Перед додаванням GitHub/GitLab remote власник проєкту окремо обирає приватність, доступи й резервний сценарій; до явного налаштування `git push` не виконується.

```powershell
git status --short --branch
git log --oneline --decorate -10
git diff
```

Перед будь-яким відновленням спершу збережіть незакомічені зміни окремим комітом або `git stash`. Не використовуйте `reset --hard`, `clean -fd` чи примусове переписування історії для звичайного виправлення конфлікту.
