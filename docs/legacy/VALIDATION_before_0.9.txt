LOWTUBE 0.6 — VALIDATION, 2026-10-11

This release:
- All production sources compiled as C# 5 / .NET Framework 4.8 / Windows x64.
- 131 core checks, 24 Google OAuth regression checks, 13 Lua seek-guard checks.
- EN/UK/RU audit: 275 entries, 260 referenced translation keys.
- Real mpv 0.37 Linux integration with synthetic local media: same PID across
  reloads, preserved start position/pause/volume/speed, separate audio loading
  and clearing, audio-only back to video, q stopping to idle without exit.
  This exercises the shipping Lua load bridge. Windows named-pipe transport,
  visible window lifecycle, DPAPI and GeForce acceleration require Windows.
- Offline Firefox cookie export verified with a synthetic cookies.sqlite and
  unreachable HTTP/HTTPS proxy. No real account cookies used in tests.
- Format-picker checks reject cap violations and exclude live/oversized cache
  entries; saved-session filtering excludes unrelated/lookalike domains.

Not measured here: cold HDD launch time or RAM use on the user's laptop,
Windows UI behavior, real signed-in YouTube playback, session longevity.
The player remains resident only while LowTube runs. The code stops/unloads
media on Stop/window close; it does not keep a video downloading while idle.
No feature removal is intended. Existing login modes, OAuth, downloads,
local feeds/history, themes/languages, audio window and buffer settings remain.

MPV DEPENDENCY HOTFIX — 2026-10-10
The exact reported mpv-x86_64-20261009-git-36abaa32d0 binary was extracted
and inspected with objdump: its import table requires vulkan-1.dll; its
archive includes d3dcompiler_43.dll but not vulkan-1.dll. This is a likely
source of 0xC0000135 on a machine without a Vulkan runtime, not proof of
which DLL was missing on the user's Windows installation.

Added: early Vulkan-loader preflight; official runtime ZIP with pinned
SHA256 and PE-machine selection; system-runtime/manual-ZIP alternatives;
persistent hash-verified download cache; captured component output, signed
and hexadecimal exit codes, diagnostic log, and preserved failed binaries.
Automatic LunarG download was blocked in the development environment
(HTTP 403, error 1010). The published ZIP hash came from the official
LunarG download page; actual runtime extraction and Windows loading remain
unverified. The manual official Runtime installer route is documented.

PowerShell 7.4.6 Linux: 12 dependency regression checks + 4 existing
installer fixture checks passed. Tests used a mocked download transport,
the shipped x64 PE, an x86-header fixture, and real local process launches.
Verified: cache reuse and corruption handling, fail-closed hashes, origin
checks, architecture selection, invalid-file rejection, process log creation

STARTUP / IN-PLAYER SETTINGS / SEEK UPDATE 0.4 — 2026-10-10
User report: a cold HDD run took about 2 minutes to open LowTube and 30 seconds
for video playback. No target-machine timing trace was available, so these
numbers are observations, not a confirmed diagnosis of one particular cause.

Implemented:
- Removed System.Web.Extensions / JavaScriptSerializer from the shipping app.
  JsonCodec.cs is a bounded first-party implementation tested directly on Linux
  and compiled against .NET Framework 4.8; no serializer adapter is used now.
  History and tool checks run after window construction. Layout is suspended
  during construction. External process creation runs off the UI thread.
- Official yt-dlp_win.zip x64 onedir distribution replaces onefile yt-dlp in
  new setup runs. UPDATE_YTDLP.cmd performs only this component upgrade with
  publisher SHA256 verification, dependency preservation and directory rollback.
  Existing onefile installs still work; the unpacked path has priority.
  No antivirus exclusions, certificate changes or administrator requirement added.
- Up to four selected-stream metadata records live in RAM for three minutes,
  keyed by URL, quality/FPS/codec/audio mode and account context. Nothing from
  this cache is written to disk. Quality/account changes select another entry;
  buffer/decoder-only changes reuse it. A manual clear is available in Settings.
- START.cmd records a launch timestamp. Startup report measures managed entry,
  window construction/first paint, history, yt-dlp operation, mpv process launch,
  IPC readiness and the first observed playback-restart event. Reports contain
  timings only, not cookies or stream URLs. Earlier events can occur before an
  IPC connection is ready; absence of a playback event is not itself a failure.
- F4 / right-click inside mpv sends a client-message to LowTube and opens a native
  settings dialog: max height, H.264/FPS limits, decoder, renderer, speed, buffer
  and safe seeking. Apply re-extracts only if needed and restarts playback at
  the current position, preserving pause and volume. Cancel leaves media alone.
- Numeric buffer fields: 5–3600 seconds ahead, 16–1024 MiB ahead per demuxer,
  0–512 MiB behind per demuxer, 1–30 seconds startup/refill threshold. Old presets
  keep their former memory values. Separate audio and video each have a buffer.
  Cache remains in RAM, with explicit independent forward/back memory caps.
- Bundled lowtube.lua pauses playback during a video seek until playback-restart
  and seeking=false. It preserves an existing user pause, handles repeated seeks,
  allows explicit user resume and fails paused with an OSD explanation after
  30 seconds. A resume-immediately-followed-by-seek race found in integration
  testing was fixed and now has a deterministic regression test.
  Audio-clock sync, initial A/V alignment and VO frame dropping are explicit.
  Precise seeking is enabled with safe mode; decoder frame dropping remains at
  mpv's default (no speculative decoder/GPU-specific flags were added).

Verified:
- Windows x64 GUI EXE builds with Roslyn C# 5 and .NET Framework 4.8 reference
  assemblies, with no errors/warnings. The binary no longer references System.Web.
- 119 core tests pass using the PRODUCTION JSON codec, including prior settings,
  channels, formats, independent buffer values, restart-state arguments, IPC
  serialization, Unicode/numeric round trips and invalid JSON bounds.
- 26 existing offline integration checks pass against yt-dlp 2026.08.19.
- Seven backend/process fixture checks pass: cache reuse, buffer-only reuse,
  quality/account separation, unauthenticated discovery despite AuthMedia,
  manual invalidation and unpacked-executable priority.
- 13 deterministic Lua/mp API tests pass (tests/test_seek_guard.py).
- Real mpv 0.37.0 on Linux, with separate synthetic H.264 and AAC streams served
  by a throttled local HTTP range server, a 5-second cache and software decoding:
  seeking past cache to 35 seconds paused and resumed successfully; A/V offset
  after resuming was about 0.006 s; an existing pause stayed paused; rapid seeks
  resumed correctly; F4 emitted the expected client-message. Ten HTTP range
  requests exercised both files. Video/audio output was null/headless: this
  validates control flow and timestamps, not visible frames or audible sound.
- PowerShell 7.4.6: four existing FFmpeg installer fixtures and twelve dependency
  fixtures pass. Seven new onedir tests pass against the actual official ZIP:
  x64 choice/PE, every copied dependency hash, targeted replacement, unrelated
  tools preserved and rollback when replacement fails. Build.ps1 syntax passes.
- Verified yt-dlp 2026.08.19 portable ZIP SHA256:
  30b4c14aafab6082becff7881e41b76df46dc43ea7633479410a91e29da492bf
- Localization audit: 225 EN/UK/RU entries, matching placeholders and 213 static
  references resolved. Numeric buffer labels are also in the same catalog.
  Lua OSD has EN/UK/RU messages and uses the language chosen when video launches.

Limits / required target-machine check:
No cold Windows HDD benchmark, Windows GUI interaction, Windows named-pipe
listener, actual Windows onedir executable startup, DXVA2 / GeForce 9300M driver
recovery or hardware A/V sync was run in this Linux environment. We cannot
promise a specific speedup or that every old-driver seek fault is eliminated.
The Linux .NET 8 test host reports a WebRequest deprecation warning; the shipping
.NET Framework 4.8 build does not. Test-only Linux binaries are not bundled.

On Windows:
1. Close LowTube, replace all application files (including player/lowtube.lua),
   keep tools, then run UPDATE_YTDLP.cmd once. Start via START.cmd for timing.
2. Settings > Startup report: record cold and warm launch separately. If still
   slow, send this report; it contains no cookies or signed stream addresses.
3. Play video; F4 or right-click > change decoder/quality/buffer > Apply. Verify
   position, volume and prior pause. Reopen the dialog to confirm saved values.
4. Seek outside the buffer, seek repeatedly, seek while paused, and quickly
   resume then seek. Verify sound does not continue alone during the seek wait.
5. If drift persists, capture Player diagnostics during the problem and compare
   with software decoding. F4 > Apply can restart the decoder at that position.
