# Стан проєкту та подальша робота

Актуальний знімок вихідного коду: LowTube 0.11.6. `AssemblyVersion` лишається 0.11.0.0, `AssemblyFileVersion` — 0.11.6.0. Бенчмарк має власну версію; експериментальний hybrid-плеєр і стабільний застосунок запускаються окремо.

## Останні зміни

- 0.11.6: закриття вікна mpv та явний quit проходять через спільний session-aware Stop; штатний вихід не запускає відновлення відтворення.
- 0.11.5: закриття скасовує незавершений запуск, а вибір якості переходить до найближчої доступної нижчої роздільності в межах обмежень FPS і кодека.
- 0.11.4: додано один обмежений повтор отримання свіжого посилання під час початкового відкриття потоку та адресне очищення невдалого запису кешу.
- 0.11.3: додано типізовані помилки каталогу й спільну паузу HTTP після 429/503 без автоматичних повторів; перевірені сторінки зберігаються після тимчасового збою.
- 0.11.2: каталог YouTube працює через InnerTube; yt-dlp залишається для потоків і завантажень. Захищена сесія читається в пам’яті.

## Збірка та межі перевірки

У Windows використовуйте `Build-All.ps1`, щоб зібрати чотири EXE разом, та `Run-Checks.ps1` для актуального тестового набору. У звіті відділяйте компіляцію, автономні перевірки, роботу WinForms та перевірку реального GPU/аудіо. .NET harness не підтверджує роботу WinForms, D3D11VA, звуку чи старих драйверів.

Історичні перевірки 0.11.6 повідомляли про успішну збірку та регулярні й нативні Windows mpv тести. Це попередні результати, а не новий запуск тестів у поточному середовищі. Актуальні результати треба фіксувати окремо від історичних.

## Hybrid експеримент

Hybrid — окремий експериментальний шлях для локального CFR H.264, а не заміна звичайного відтворення. Він ділить роботу на GOP-и, запускає CPU або D3D11VA workers і передає кадри через черги в mpv. Це не zero-copy. Звітів вимірювань у репозиторії немає; перед оптимізацією отримайте свіжі результати або визначте, яких вимірювань бракує. Не робіть висновків про плавність лише з лічильника dropped frames: враховуйте просування media-time, wall time та A/V sync.

## Наступні етапи

1. Зрозуміле оновлення списків: одна дія повтору/оновлення, збереження поточного вмісту до успішної відповіді та виразний стан кінця списку, кешу й помилок.
2. Локальна бібліотека: пошук, фільтрація та версійний експорт/імпорт плейлистів і каналів. Формат та правила злиття треба погодити до реалізації; пошкоджений імпорт не має змінювати бібліотеку.
3. Перевірка випуску у Windows: пошук, сесія, плейлист, resume, якість, audio-only, еквалайзер, черга, завантаження та повторне використання mpv. Окремо фіксувати перевірки апаратного декодування й A/V sync.
4. Hybrid: спершу отримати вимірювання bottleneck-ів; не починати native/shared-memory переписування без даних.

Windows 7 32-bit, Linux та Android залишаються можливими майбутніми платформами, а не заявленою підтримкою. Збережіть стабільний і експериментальний запуск окремими.

## Межі даних і безпеки

Cookies, OAuth-конфігурація, браузерні профілі та локальні дані користувача не належать до резервних копій проєкту чи діагностичних звітів. Не комітьте cookies, токени, підписані URL, профілі браузера або особисті шляхи. Перед публікацією перевіряйте нові звіти та знімки на такі дані.
