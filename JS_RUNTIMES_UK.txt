Оновлення 0.6.4: стандартний рушій тепер Node.js 22. START.cmd та прямий запуск EXE використовують Node; для QuickJS-NG використовуй START_QUICKJS_NG.cmd. Нижче — інструкція попереднього порівняльного пакета 0.6.3.

LowTube 0.6.3 — порівняння JavaScript-рушіїв (Windows 10 x64)

Це патч для наявної LowTube 0.6 / 0.6.1 / 0.6.2. Повна збірка не включена.
1. Закрий усі вікна LowTube. Зроби копію поточної папки програми для відкату.
2. Розпакуй JS_Runtimes_Patch у папку з LowTube.exe, погодься на заміну файлів.
3. Розпакуй один або всі три пакети рушіїв у ТУ САМУ папку.
4. Запускай START_NODE22.cmd, START_DENO.cmd або START_QUICKJS_CLASSIC.cmd.
   Звичайний START.cmd продовжує використовувати встановлений QuickJS-NG.
   START_QUICKJS_NG.cmd явно вибирає цей контрольний варіант.
Ні інсталяція рушіїв у систему, ні права адміністратора не потрібні.

ВЕРСІЇ
Node.js 22.23.3 x64; Deno 2.9.7 x64; QuickJS classic 2026-06-04 x64.
QuickJS-NG не замінюється. SETUP.cmd не оновлює ці додаткові пакети.
Ярлик спершу виконує короткий локальний тест JavaScript. При помилці
програма не запускається, а консоль лишається відкритою. Сам тест НЕ
перевіряє всі можливі інструкції процесора або всі сценарії YouTube.
Не запускай кілька варіантів одночасно. Вибір діє тільки для цього запуску.
Налаштування та збережена сесія залишаються спільними для всіх варіантів.

СУМІСНІСТЬ І ОЧІКУВАННЯ
older dual-core CPU older dual-core CPU (Penryn): до SSE4.1; немає SSE4.2/AVX/AVX2.
Node22 — перший кандидат: V8 перевіряє SSE2 та CMOV як обов'язкові,
а SSE4.2 та AVX вмикає після перевірки можливостей CPU.
Deno — другий кандидат, також використовує V8; yt-dlp рекомендує Deno.
QuickJS classic — компактний альтернативний інтерпретатор.
Bun виключено: навіть baseline x64 вимагає SSE4.2 (Nehalem).
Linux-версії всіх трьох пройшли короткий JS-тест під QEMU 8.2.2
з моделлю CPU Penryn. Це НЕ сертифікація Windows-бінарників на older dual-core CPU.
Windows-запуск на реальному ноутбуці тут не перевірений.
Не виміряно, який рушій швидший на твоєму ПК. Node/Deno з JIT мають
потенціал скоротити CPU-час розв'язання JS, але можуть споживати більше
пам'яті. Завантаження більших EXE з HDD також може впливати на результат.
Заміна JS впливає на отримання посилань, а не на декодер або FPS у mpv.

ЯК ПОРІВНЯТИ
Для кожного рушія закрий програму, запусти відповідний CMD, відкрий те саме
відео з однаковими якістю, FPS/H.264 та сесією. Повтори 2–3 рази з новим
запуском програми. Мережа та дисковий кеш можуть змінювати результати.
Повторне відкриття всередині одного запуску може використовувати кеш
форматів і зовсім не запускати JS — це не вимір швидкості рушія.
У startup.txt дивись JS-runtime, format cache HIT/MISS, yt-dlp operation,
CPU-total, peak-RAM-observed та час до mpv playback-restart.
Після закриття програми CMD копіює звіт у:
%LOCALAPPDATA%\LowTube\startup-node22.txt
%LOCALAPPDATA%\LowTube\startup-deno.txt
%LOCALAPPDATA%\LowTube\startup-quickjs-classic.txt
%LOCALAPPDATA%\LowTube\startup-quickjs.txt (через START_QUICKJS_NG.cmd)
Оригінальний startup.txt, як і раніше, перезаписується кожним запуском.
Копія для одного рушія перезаписується наступним тестом цього рушія.

ЩО ЗМІНЕНО
Додано вибір рушія окремими CMD; обраний профіль входить у ключ кешу.
Додано імена Node.js/Deno і профіль рушія в діагностику. Виправлено перший
CPU-інтервал: відлік починається після встановлення початкової точки.
Функції авторизації, пошуку, завантажень, mpv та налаштування збережені.
151 автоматична перевірка пройшла; C#5/.NET4.8 x64 збірка успішна;
переклади EN/UK/RU перевірені. Native Windows UI та процеси тут не тестувалися.
