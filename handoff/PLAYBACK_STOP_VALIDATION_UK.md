# Закриття відео та вибір нижчої якості — 0.11.5

## Зміни

Закриття вікна mpv / Q тепер негайно скасовує покоління запуску, поточну сесію, очікування завантаження й підготовлений наступний елемент. Lua надсилає ідентифікатор закритої сесії та вимикає її телеметрію перед очищенням native-плейлиста. Кнопка Stop використовує те саме очищення Lua. Процес mpv залишається придатним для наступного явного запуску.

До виправлення Lua Stop не змінював покоління Start, а UI очікував InvalidatePrepared до очищення resumeSession. Це залишало можливість продовжити запуск або відновлення після закриття. Тепер UI скасовує пов'язані операції до очікування очищення. Відновлення перевіряє власника після Start; EOF і прийняття підготовленого елемента перевіряють актуальну сесію. Невдалий Start завершує очищення під своїм семафором, щоб відкладений Stop не зупинив наступний запуск.

Запізнілий Stop іншої завершеної сесії або повідомлення про вже скасований підготовлений елемент ігноруються. Події end-file перевіряються за playlist_entry_id; події попереднього файла до start-file нового не завершують новий Start. Поля й відкладений тестовий on_load відповідають [офіційній документації mpv](https://mpv.io/manual/stable/#list-of-events) та [Lua hooks](https://mpv.io/manual/stable/#extras).

Вибір нижчої роздільності вже допускався фільтром, але залежав від порядку форматів yt-dlp і віддавав перевагу окремому відеопотоку навіть за наявності вищої комбінованої якості. Тепер кандидати явно ранжуються за висотою: найбільша додатна висота ≤ обраного максимуму. За однакової висоти збережено перевагу окремого відео+аудіо. Перевіряються наявність аудіо, DRM, URL, FPS та H.264. Наприклад, 1440p при максимумі джерела 1080p обирає 1080p; якщо 720p доступне лише при 60 FPS, увімкнений ліміт 30 FPS може обрати 480p.

Збережений максимум не змінюється, тому наступне відео може використати повну обрану якість. Якщо жодного сумісного потоку ≤ максимуму немає, залишається явне повідомлення про відсутність формату. Автоматичне підвищення роздільності, вимкнення лімітів або додаткові запити yt-dlp не додаються.

## Перевірки

`Run-Checks.ps1 -WindowsMedia` збирає всі чотири власні EXE разом через Build-All.ps1. C# 5 / .NET Framework 4.8; AssemblyVersion — 0.11.0.0, AssemblyFileVersion — 0.11.5.0.

- 515 звичайних перевірок, включно з 12 новими сценаріями вибору якості.
- 14 native Windows mpv перевірок: 2 попередні сценарії невдалого відкриття/свіжого повтору та 12 сценаріїв Player/Lua Stop, підготовки й переходу.
- 506 записів EN/UK/RU; аудит 410 використаних ключів.
- Необов'язковий Lua sampler через Lupa пропущено: залежність відсутня. Нові Stop-сценарії запускають справжній Lua встановленого mpv.

WindowsPlayerStopTests використовує власний 4-секундний WAV, null audio/video, Windows named pipes і штатний Player. Тестовий локальний Lua hook затримує один on_load на 0,5 секунди: CLOSE_WIN у цей момент скасовує Start, не запускає fresh-link retry та залишає плеєр зупиненим після завершення hook. Також перевірено Q з підготовленим елементом, відкидання запізнілих повідомлень, повторне використання того самого процесу, звичайний перехід при EOF і програмний Stop. Є загальний ліміт 25 секунд, ProcessJob і очищення власного тимчасового каталогу. Інструменти користувача не оновлювалися.

Це перевірки компіляції, автономної логіки й Windows IPC/Lua. Вони не підтверджують фізичне натискання хрестика вікна, роботу драйвера GPU, аудіопристрою чи плавність відтворення YouTube. Мережа, збережена сесія й реальні cookies не використовувалися.

Патч LowTube_0.11.5_patch_2026-10-15.zip кумулятивний відносно перенесення 0.11.1, містить лише нові/змінені файли та чотири власні EXE. Перед накладанням закрити попередній LowTube; замінити також player/lowtube.lua. Tools і приватні дані не включені. Поточний маніфест — PLAYBACK_STOP_PATCH_SHA256.json; попередні маніфести збережено.
