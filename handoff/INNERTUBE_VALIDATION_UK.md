# LowTube 0.11.2 — аналіз і перевірка InnerTube

Дата: 2026-10-15. C# 5, .NET Framework 4.8, WinForms, Windows x64. AssemblyVersion збережено 0.11.0.0; AssemblyFileVersion — 0.11.2.0. Усі чотири власні EXE перебудовано разом.

## Що виявлено й зроблено

| Проблема | Реалізована зміна |
|---|---|
| Для пошуку, каналів і списків запускався yt-dlp із підготовкою середовища медіаінструментів | Backend.Browse, PlaylistPage, SessionChannels, ChannelBatch і ResolveChannel використовують окремий InnerTubeClient |
| Фонове уточнення дати викликало повне Resolve із потоковими форматами | Новий VideoMetadata читає лише videoDetails і microformat з HTML watch-сторінки; streamingData не повертається й не кешується |
| InnerTube має кілька поколінь карток | Парсер підтримує video/grid/playlist/channel renderers, сучасні lockupViewModel та shortsLockupViewModel |
| Нативні сторінки API не збігаються з розміром сторінки UI | Opaque continuation-токени, збереження залишку сторінки, розміри UI 1–250, кеш сторінок назад |
| Приватні/видалені елементи можуть зсунути позиції плейлиста | Недоступні позиції враховуються у пагінації; однакові відео в різних позиціях не видаляються |
| Постійний кеш усіх елементів довгого списку збільшував би пам’ять | Ковзне вікно до 5000 позицій на список; послідовне читання понад 5000 підтримується; витіснені старі сторінки перебудовуються |
| Можливі повтори токенів та порожні нескінченні продовження | Перевірка останніх 256 токенів і ліміт 64 API-запитів на одну операцію читання списку |
| Прострочена сесія могла б непомітно показати гостьовий список | Перевірка LOGGED_IN та loggedOut у відповіді API; помилка для запитів особистих списків |
| Для каталогу захищена сесія не потребує cookies.txt на диску | DPAPI-сесію читаємо в пам’ять; залишено наявний шлях Lease для медіа |
| Офлайн-тест аргументів вимагав установленого FFmpeg | Формування аргументів відокремлено від пошуку EXE; тестуємо зі штучними шляхами |
| Консольні тести DownloadManager створювали гонки, яких немає в його UI-контракті | FeatureTests та ContinuityTests виконують async-продовження послідовно через тестовий SynchronizationContext |

Збережено mpv reuse/IPC, resume, чергу, еквалайзер, завантаження, локальні плейлисти, налаштування, три мови й теми. Експериментальний hybrid не інтегровано у стабільний плеєр. Зміни не доводять прискорення чи зниження CPU: порівняльних вимірювань продуктивності не проводили.

## Межі між провайдерами

- InnerTube HTTP: search, browse, navigation/resolve_url; YouTube recommendations/subscriptions/history/channels; вкладки videos/shorts/streams/playlists; наповнення й пагінація плейлистів.
- Метадані без медіа: HTML watch-сторінки та її JSON videoDetails/microformat. Це не запит потоків через player API.
- yt-dlp: Resolve для відтворення, підготовки наступного елемента та відновлення потоку; список медіаформатів; відео- й аудіозавантаження; погоджений локальний експорт cookies через offline fixture.
- Автоматичного повернення до yt-dlp для каталогу немає. Старі префікси `ytsearch...`, `:ytrec`, `:ytsubs`, `:ythistory` залишилися внутрішніми сумісними ідентифікаторами, а не командами запуску yt-dlp.
- Наявний Google OAuth / Data API шлях не видалено.

## Захист і межі ресурсів

- Один активний запит каталогу між усіма клієнтами; поточний планувальник і його фонові бюджети збережено. Один пакет каналів може містити кілька послідовних HTTP-запитів.
- Тайм-аут одного HTTP-запиту — 25 с; однієї операції каталогу — 150 с; скасування перериває HttpWebRequest. Пошук старої довільної сторінки з нуля може досягти ліміту 64 запитів і завершитися видимою помилкою.
- Відповідь обмежена 8 MiB після розпакування; JSON також має існуючі обмеження глибини. Перенаправлення HTTP вимкнені, адреса відправлення фіксована на www.youtube.com.
- До чотирьох кешованих клієнтів і чотирьох списків на клієнт. Конфігурація WEB оновлюється через 15 хв, списки — через 10 хв. Явний запит першої сторінки через Backend оновлює початок списку одразу.
- Синхронізація каналів обмежена 5000 записами, як попередній шлях yt-dlp. Кеші каталогу з конфігурацією й токенами продовження — лише в пам’яті.
- Cookies фільтруються за доменом YouTube, шляхом і строком дії; підтримано HttpOnly та SAPISID/1P/3P підписи, індекс акаунта й brand page ID. Cookies та Authorization не пишуться в журнал.
- Підтримано saved, cookies.txt та старі browser/firefox режими. Для останніх yt-dlp лише локально експортує cookies; мережевий каталог отримує InnerTube. Гостьові запити не імпортують cookies.

## Проведені перевірки

`Build-All.ps1` успішно зібрав LowTube.exe, LowTube.Benchmark.exe, LowTube.Hybrid.exe і LowTube.Hybrid.Compare.exe системним компілятором .NET Framework.

`Run-Checks.ps1` успішно виконав:

| Набір | Перевірок |
|---|---:|
| CoreTests | 283 |
| FeatureTests | 25 |
| GoogleTests, включно з реальним localhost callback на штучних даних | 24 |
| ContinuityTests | 26 |
| InnerTubeTests, без мережі й реальних сесій | 49 |
| BenchPlanTests | 45 |
| Разом | 452 |

Аудит локалізації: 497 повних EN/UK/RU записів, 402 використані ключі. Lua sampler пропущено: немає необов’язкового Lupa. `test_session_export.py` не запускали: Python-модуль yt_dlp відсутній, а встановлювати залежності користувача не потрібно для цього патча.

Окремий `Test.InnerTubeTests.exe --public` використовує лише `new Settings { Auth="none", AuthMedia=false }`, не читає налаштування чи сесії користувача. Перевіряються 9 публічних сценаріїв: пошук, продовження пошуку, watch-метадані, @handle, відео каналу, пошук плейлистів, елементи плейлиста, Shorts і трансляції. Попередню відмінність HTML-конфігурації було відтворено й виправлено: парсер пропускає JS-виклики ytcfg.set з аргументами, які не є JSON-літералами.

У sandbox для тестів TEMP/TMP було тимчасово спрямовано в `.checks-temp` цього проєкту; це змінні лише процесу перевірки. Повний набір потребував дозволу на localhost для наявних OAuth-тестів. Жодні встановлені інструменти або постійні параметри Windows не змінювалися.

## Що ще потрібно перевірити

1. Реальну збережену сесію: персональні рекомендації, історію, підписки, brand account та прострочення cookies. Зараз ці шляхи покриті лише штучними даними; реальні користувацькі сесії не читалися.
2. GUI, mpv reuse/IPC, аудіо й завантаження на Windows з установленими медіаінструментами. У цьому знімку tools містить лише інвентаризацію, тому медіа-сценарії не запускалися.
3. D3D11VA/старий драйвер і плавність на ASUS X71SL — окрема апаратна перевірка. Результати компіляції, консольних тестів і HTTP не замінюють її.
4. InnerTube — внутрішній інтерфейс YouTube; зміни схем, consent, 403/429 або вимога входу можуть потребувати оновлення клієнта. Помилки видимі; циклічних повторів або обходу через медіаекстрактор немає.
5. Дані hybrid 0.5 залишаються потрібними до обговорення нового конвеєра декодування. Підстав для native/shared-memory переписування цей патч не додає.

Для повторення після закриття LowTube:

```powershell
.\Run-Checks.ps1
# Додатково, лише коли потрібна перевірка поточного публічного YouTube:
.\Test.InnerTubeTests.exe --public
```

Вихідні матеріали для перевірки протоколу: [YouTube.js Session](https://github.com/LuanRT/YouTube.js/blob/main/src/core/Session.ts), [yt-dlp YouTube base](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/youtube/_base.py), [yt-dlp tab renderer support](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/youtube/_tab.py). Runtime-залежності від цих бібліотек не додано. Надане посилання ChatGPT Share отримати не вдалося; реалізація спирається на код проєкту й перевірки.

## Застосування патча

Закрийте LowTube та його тестери, розпакуйте `LowTube_InnerTube_patch_2026-10-15.zip` поверх кореня проєкту зі збереженням вкладених каталогів. Архів містить лише змінені/нові файли та чотири узгоджені EXE; сторонні tools і користувацькі дані не входять. Історичні TRANSFER_SHA256.json та інші контрольні суми збережено. Окрема INNERTUBE_PATCH_SHA256.json описує файли цього патча.
