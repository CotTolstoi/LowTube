# LowTube 0.11.4 — відновлення після помилки відкриття потоку

Дата: 2026-10-15. Повідомлення користувача: mpv не зміг відкрити вибраний потік і запропонував очистити кеш.

## Що встановлено

У startup report дві спроби з обмеженням 30 FPS завершилися помилкою після успішного отримання свіжих метаданих; наступна спроба з кешем після вимкнення обмеження відкрилася. Тому сам застарілий кеш не пояснює всі збої, а часове співпадіння з перемикачем FPS не доводить причину.

Надане користувачем відео перевірено через вже збережену сесію штатним Backend/yt-dlp. Для обох значень FPS30 вибрано однаковий формат 399+140: AV1 1080p30 та окремий AAC. Обидва варіанти mpv відкрив із кодом завершення 0 у короткому тесті до трьох кадрів, з vo=null, ao=null, hwdec=no. Cookies і підписані URL не виводилися, сирий JSON не зберігався й до патча не входить. Налаштування й сторонні інструменти не змінювалися.

Попередня окрема гостьова перевірка іншого публічного відео отримала HTTP 429 та лише storyboard-формати. Після виявлення 429 гостьові повтори зупинили. Це спостереження не встановлює HTTP-статус попередньої помилки користувача: старий startup report його не містив.

Точну причину первинного збою не відтворено. Перевірки не доводять плавність, коректність аудіовиходу або роботу GPU.

## Зміни

- Замість загальної поради очистити весь кеш використовується фактична категорія file_error з події mpv end-file. Значення нормалізується через фіксований список; невідомий текст не потрапляє до повідомлення чи звіту.
- Для початкового відкриття, audio-only, черги через звичайний Play та застосування якості додано один повтор із новими метаданими після StreamOpenException. Він працює тільки за увімкненого AutoRecover. Другий збій завершує спробу; помилка отримання метаданих, Stop/Cancel та помилки ініціалізації аудіо/відеовиходу нових повторів не запускають.
- Після помилки відкидається лише кеш відповідного відео в поточному контексті авторизації. Інші потоки й каталог InnerTube не очищуються.
- Висота, FPS, H.264, decoder, buffer, resume/position, pause, volume та speed автоматично не послаблюються. Відновлення вже активного потоку з його існуючими двома спробами не розширювалося.
- Startup report містить безпечні ідентифікатори вибраних форматів, протокол і кодеки, причину mpv та розпізнані підказки HTTP 403/404/429/timeout. Розбір рядків журналу використовується лише як діагностика; рішення про повтор приймається за типом помилки відкриття.
- У виводі mpv приховується весь URL, включно зі шляхом: підпис може бути не лише в query. Рядки Cookie/Authorization приховуються.

## Перевірки

Усі чотири EXE зібрано разом через Build-All.ps1. C# 5 / .NET Framework 4.8; AssemblyVersion збережено 0.11.0.0, AssemblyFileVersion та startup report — 0.11.4.

`Run-Checks.ps1 -WindowsMedia` успішний:

- 503 перевірки основних наборів, включно з 18 новими перевірками відкриття й повтору;
- 2 додаткові локальні перевірки встановленого Windows mpv: реальна подія loading failed для відсутнього файла; нове відкриття через штатний Lua load та C#-повтор у тому самому процесі;
- 506 повних EN/UK/RU записів і 410 використаних ключів;
- Lua sampler пропущено через відсутність Lupa.

WindowsStreamOpenTests створює власний короткий WAV, запускає mpv без вікна, звуку та GPU, використовує Windows named pipe і ProcessJob, має 20-секундний загальний ліміт і прибирає власний тимчасовий каталог. Мережа й користувацька сесія йому не потрібні. Без прапорця WindowsMedia виконуються звичайні набори; сторонні інструменти потрібні лише для додаткового native-тесту.

## Якщо помилка повториться

Після встановлення патча закрити старий LowTube й запустити його знову. Залишити потрібне обмеження 30 FPS. Якщо і контрольований повтор завершиться невдало, відкрити Settings → Startup report: він уже міститиме формат, причину mpv і доступні HTTP-підказки. Не надсилати cookies.txt, сесію, сирі метадані або повні URL медіапотоків.

Архів LowTube_0.11.4_patch_2026-10-15.zip кумулятивний відносно початкового перенесення 0.11.1 та придатний для 0.11.2/0.11.3. Він містить лише змінені/нові файли та чотири власні EXE. Tools і приватні дані не включені. Поточний маніфест — STREAM_OPEN_PATCH_SHA256.json; попередні маніфести залишаються історичними.
