# Наступні етапи LowTube

Стан: 2026-10-15. Перший етап виконано у 0.11.3; виправлення обробки відкриття потоку у 0.11.4 описано в STREAM_OPEN_VALIDATION_UK.md. Прискорення запуску відео відкладено за вказівкою користувача: попереднього отримання потоків для вибраної картки, зміни стартового буфера й нових фонових медіазапитів цей план наразі не впроваджує.

## 1. Стійкість каталогу — реалізовано в 0.11.3

Мета: тимчасова помилка не повинна перетворювати список на порожній або запускати повторні мережеві запити без контролю.

- Додано класифікацію помилок: мережа, HTTP, невідома відповідь, відхилена сесія, ліміт операції, пауза запитів.
- Після HTTP 429/503 нові HTTP-запити каталогу блокуються локально. Враховується Retry-After у секундах або форматі RFC 1123; за відсутності придатного значення — 60/30 секунд відповідно. Максимум паузи — 24 години, мінімум — 1 секунда. Пауза спільна для виробничих клієнтів, а очищення кешу її не скидає.
- Під час паузи вже кешовані сторінки залишаються доступними. Немає таймерів повторного запиту, сплячих задач чи автоматичного retry.
- Після обриву мережі, тайм-ауту, скасування або ліміту 64 запитів зберігаються лише повністю перевірені сторінки. Наступний явний повтор продовжує токен із них, включно з повтором першої сторінки через Backend.
- Пошкоджений JSON, невідоме продовження чи непридатний токен не вважаються кінцем списку; некоректний стан відкидається. Чужий videoId у watch-метаданих відхиляється.
- Відео, плейлисти та канали повертаються окремими об’єктами. Зміна картки або черги не змінює внутрішній кеш.
- Пакет каналів зупиняється після мережевої помилки, тайм-ауту, відхилення сесії, 429 або серверного збою; уже успішні канали зберігаються. Окремий 404 не зупиняє решту пакета.

Збережено обмеження пам’яті й кількості запитів, C# 5 / .NET Framework 4.8, усі наявні публічні сигнатури Backend. Додано перевантаження конструктора з клієнтом каталогу для перевірки інтеграції на штучному транспорті. Медіашлях yt-dlp/mpv і окремий hybrid не змінено.

### Перевірка першого етапу

Build-All.ps1 та Run-Checks.ps1 успішні на Windows; усі чотири EXE зібрано разом. AssemblyVersion лишається 0.11.0.0, AssemblyFileVersion — 0.11.3.0, заголовок startup report відповідає патчу.

Локалізація: 498 EN/UK/RU записів, 403 використані ключі. Необов’язкову Lua-перевірку пропущено через відсутність Lupa.

Окремо `Test.InnerTubeTests.exe --public` успішно перевірив 9 поточних гостьових сценаріїв YouTube: пошук, пагінацію, watch-метадані, @handle, вкладку відео, пошук плейлистів, плейлист, Shorts і трансляції. Для помилок 429/503, скасування, HTTP-date, відновлення й ізоляції кешів використані лише штучні відповіді; реальний сервіс навмисно не навантажувався до ліміту. Таймерні очікування для пауз не потрібні: тести використовують керований годинник.

Реальні приватні сесії не читалися. GUI, відтворення, завантаження, аудіо й GPU у цьому етапі не перевірялися. Консольні тести не замінюють ці перевірки. Наявні встановлені медіаінструменти, їх інвентаризацію й постійні налаштування Windows не змінювали; сторонні файли tools не входять до патча.

## 2. Зрозуміле оновлення списків — наступний етап

- Одна дія «Оновити / повторити» для поточного списку з урахуванням його типу й сторінки.
- Чітко відрізняти порожній результат, кінець списку, показ кешу, тимчасову мережеву помилку й необхідність оновити сесію.
- Зберігати поточні картки, вибір і прокрутку до успішного оновлення.
- Передавати ознаку наявності наступної сторінки в UI додатковим API без зміни чинних сигнатур.

Критерій готовності: повтор працює для пошуку, каналу, плейлиста й підписок; збій не стирає видимий список; кнопка наступної сторінки не веде за підтверджений кінець; пауза 429 не створює нових HTTP-запитів. Потрібна також ручна WinForms-перевірка навігації.

## 3. Локальна бібліотека й резервне копіювання — заплановано

- Пошук і фільтрування локальних плейлистів, черги та збережених каналів.
- Явний експорт та імпорт плейлистів/каналів у версіонованому форматі з перевіркою URL, кількості записів і дублікатів.
- Попередній перегляд імпорту: що додається, що вже існує; без прихованого видалення поточних записів.
- Cookies, OAuth-конфігурація й браузерні профілі до такого резервного копіювання не входять.

До реалізації імпорту потрібно узгодити формат і поведінку об’єднання: це істотна зміна роботи з даними користувача. Самих файлів користувача зараз не імпортували й не експортували.

Критерій готовності: цикл експорт → імпорт зберігає порядок і назви; пошкоджений файл не змінює бібліотеку; повторний імпорт має передбачуваний результат; скасування залишає дані недоторканими.

## 4. Перевірка випуску на цільовому обладнанні — заплановано

- Короткий сценарій для Windows 10 x64: пошук, сесія, плейлист, resume, перемикання якості, audio-only, еквалайзер, черга, завантаження, mpv reuse.
- Перевірка набору сторонніх інструментів і їх сумісності зі старими CPU; жодних x86_64-v3/AVX-залежних збірок.
- Приватна діагностика: версії й етапи помилок без cookies, токенів, підписаних URL та браузерних даних.
- На ASUS X71SL окремо перевірити actual hwdec, просування media-time відносно wall time та A/V sync. Тривалі бенчмарки — лише після пояснення мети.

Критерій готовності: протокол ручного тесту з версіями інструментів, результатами й окремо зазначеними пропусками. Стабільний та експериментальний плеєри залишаються окремо запускними.

## Окремі відкладені напрями

- Прискорення старту: повернутися після окремого рішення користувача.
- Hybrid: спочатку отримати звіт 0.5 й визначити вузькі місця; native/shared-memory переписування не розпочинати без даних та обговорення.
- Windows 7 32-bit, Linux та Android залишаються backlog, а не заявленими підтримуваними платформами.

## Артефакт поточного етапу

`LowTube_0.11.3_patch_2026-10-15.zip` містить тільки змінені/нові файли відносно початкового перенесення 0.11.1, включно з інтеграцією 0.11.2 і чотирма узгодженими EXE. Його можна застосувати поверх 0.11.1 або 0.11.2, попередньо закривши LowTube та тестери. Tools і дані користувача до архіву не входять. `RELIABILITY_PATCH_SHA256.json` описує поточні файли; TRANSFER_SHA256.json та INNERTUBE_PATCH_SHA256.json залишаються історичними знімками своїх версій.
