# Повторне відкриття після хрестика плеєра — 0.11.6

## Відтворена причина

Попередній патч перевіряв Q/CLOSE_WIN та спільний Lua Stop. Проте кнопка хрестика у player/lowtube_osc.lua мала окремий callback з mp.commandv("quit"). Він завершував процес, а Player сприймав закриття IPC як помилку відтворення. PlaybackFailed міг викликати автоматичне відновлення й повторне відкриття.

Новий native-тест із raw quit на попередній збірці 0.11.5 відтворив проблему: перевірка «native quit is Stop rather than a recoverable IPC failure» завершилася невдало, тоді як попередні 12 Stop-перевірок пройшли.

## Виправлення

- Хрестик OSC тепер викликає спільний lowtube-stop. Той самий callback доступний через script-binding lowtube_osc/close-player і перевіряється зі справжнім завантаженим OSC. Системний CLOSE_WIN та Q збережені.
- end-file з причиною quit скасовує сесію, покоління Start і підготовлений елемент до фільтрації playlist_entry_id, включно з незавершеною заміною потоку. Такий вихід не стає помилкою для відновлення.
- Завершення mpv після EOF може не мати додаткового end-file. Крім того, [Windows IPC mpv](https://github.com/mpv-player/mpv/blob/master/input/ipc-win.c) закриває клієнта на MPV_EVENT_SHUTDOWN, не передаючи цю подію як JSON. Після розриву IPC Player один раз очікує завершення процесу поза UI-потоком, максимум 500 мс. Код виходу 0 скасовує збережену сесію та її відновлення. Це не фонове опитування.
- Повторні сигнали Stop/quit після очищення сесії й replacingSession не дублюють Stopped.
- Ненульовий вихід або неочікувана втрата процесу/IPC залишаються помилкою. Власник помилки фіксується до завершення TaskCompletionSource, оскільки його continuation може синхронно очистити Player.

Визначення причин quit/stop/error: [офіційні події mpv](https://mpv.io/manual/stable/#list-of-events). API Backend, вибір якості, обмеження FPS/кодека, yt-dlp/InnerTube та hybrid-архітектура не змінені.

## Перевірки й межі

Усі чотири власні EXE зібрано разом через Build-All.ps1. C# 5 / .NET Framework 4.8, AssemblyVersion 0.11.0.0, AssemblyFileVersion 0.11.6.0.

`Run-Checks.ps1 -WindowsMedia`:

- 515 звичайних C# перевірок.
- 23 native Windows mpv перевірки: 2 відкриття/повтору плюс 21 Stop/OSC/quit/переходу/IPC. Попередні 12 сценаріїв збережено.
- Додатково перевірено точний callback OSC та повторне використання процесу; raw quit із підготовленим наступним елементом; quit під час затриманого on_load без fresh-link retry; штатний idle-вихід після EOF; примусове завершення власного тестового процесу як помилку.
- 506 повних EN/UK/RU записів, 410 використаних ключів. Необов'язковий Lua sampler пропущено через відсутність Lupa; native-перевірки виконують встановлений mpv і обидва shipped Lua-скрипти.

Fixtures створюють власні WAV/короткий Lua hook у тимчасовому каталозі та використовують null audio/video, Windows named pipes, ProcessJob і тайм-аути. Мережа, cookies, сесія та дані користувача не використовуються. Інструменти й налаштування користувача не оновлювалися. Фізичне натискання хрестика мишею, справжнє аудіо й GPU-драйвери цим прогоном не перевірені.

Поточні файли проєкту та чотири EXE вже оновлено. Для перенесення — кумулятивний LowTube_0.11.6_patch_2026-10-17.zip, маніфест OSC_CLOSE_PATCH_SHA256.json. Закрити попередній LowTube й замінити всі файли патча, включно з player/lowtube_osc.lua та player/lowtube.lua. Tools і приватні дані не включені; історичні архіви та маніфести збережені.
